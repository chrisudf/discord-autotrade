# 昨晚复盘的评判标准

这份文件是复盘的**唯一事实来源**。Claude 的定时任务 `autotrade-nightly-review`
每早读它来决定看什么、怎么写。想改复盘的关注点，改这里就行，不用碰定时任务本身。

调用方会先把这三份素材的具体路径告诉你：

- **日志摘要** `logdigest_YYYY-MM-DD.txt` —— 概览统计 + ERROR 直方图 + **折叠掉重复刷屏之后的整晚日志全文**。**从这份开始读。**
- **数据库摘要** `digest_YYYY-MM-DD.txt`（当晚开仓 / 事件流 / 下单记录 / 收到的全部原始消息 / 未平持仓，时间已转成本机本地时区）
- **整晚终端日志** `autotrade_YYYY-MM-DD_overnight.txt` —— 原文，**多数情况下不需要通读**，只在摘要里发现异常、要看被折叠掉的细节时按行号回查。

⚠️ **两份摘要各有盲区，必须交叉看，别拿一份当全貌：**

- **`digest` 看不见卖出侧。** 它的数据全来自 `trades.db`，而 `orders` 表**只记买单** ——
  8/13 那晚 `success=0` 是 0 行，1918 次 naked-short 拒单和 EOD 卖单在整个库里查无此事。
  只读 `digest` 会得出"当晚 3 单全成、一夜平静"的结论，而真相是止盈对着一张不存在的仓位
  打了一整夜。**卖出侧的一切（拒单、TP/SL 触发、EOD 强平）只能从日志看。**
- **`logdigest` 的折叠会吞掉中间过程。** 同一条记录重复超过 20 次时只保留首末两条
  （中间有 `⋮⋮⋮ 共 N 次` 标注）。要看被折叠掉的那些，回原始日志。

要判断解析为什么失败就读 `autotrade/parsing/signal_parser.py` 和 `autotrade/listener/`。

**不要调用 Bash。** 定时任务是无人值守跑的，Bash 会触发权限确认，而那时没人去点
—— 实测卡死过一次（2026-08-05 早上，一条 `ls` 把整个复盘挂了 2.5 小时）。
摘要里已经有了当晚全部数据库记录，正常复盘用不到 `sqlite3`。真需要更细的数据，
就在回答里说明要查什么，让人手动跑。

**别假定 Grep / Glob 存在。** 两个调用方拿到的工具集不一样：

- `ops/opus_review.sh`（CLI）用 `--allowedTools "Read" "Grep" "Glob" "Write"`
  显式给全，能用。
- Claude app 的定时任务**只给 Read**（2026-08-06 实测：`ToolSearch` 连
  Grep/Glob 都搜不到）。这是 app 侧的工具集限制，不是权限问题 ——
  `settings.json` 里没有对应开关可放开，和"定时任务的模型被写死成 Sonnet"
  属于同一类限制（见 `ops/opus_review.sh` 顶部注释）。

所以：**直接用 Read 开工，缺 Grep 就别找了**（实测有一轮为了拿 Grep 连开 7 次
ToolSearch，纯浪费）。

**别再假定"整晚日志两三百行、Read 全文扛得住"** —— 这句话曾经写在这里，
连续两晚都是错的：8/13 是 8183 行 / 1.09 MB，8/14 是 3779 行，都是被同一条
拒单循环刷出来的。现在的正确姿势是：**读 `logdigest`（折叠后通常五百行上下），
只在需要被折叠掉的细节时才用 `offset`/`limit` 回查原始日志的对应时段。**

**要读源码时先读 `README.md` 的「目录结构」小节按图索骥，别猜文件名。**
2026-08-06 那次为了找 edit handler 猜了 4 个路径全错
（`listener/discord_listener.py`、`client.py`、`bot.py`、`listener.py` 都不存在），
最后靠 README 的目录树才定位到 `listener/router.py`。那份树是准的。

先把两份摘要整个读完，再决定要不要回原始日志。

**报告要一次写完整。** §1 到 §5 一节都不能少 —— 调用方按"文件里有没有
`## 5.`"判断这次复盘算不算成功，缺了会触发一次续跑重来。8/13、8/14 连续两晚
都是跑满 44-61 分钟、证据全核完了，断在写文件之前，一个字没留。所以**别把
写文件留到最后一刻**：可以先把骨架和已经确定的小节写进去，再逐节补。

两个格式上的坑，先记住：

- 摘要是 `列 | 列 | 列` 的一行一条记录；原文里的换行已被压平成 ` / `。
- **喊单机器人每条消息都会发中英两遍**（相隔 2-4 秒，msg_id 不同）。统计条数时按语义
  去重，别把同一个信号算成两条。

## 要回答的问题

按重要性从高到低：

1. **漏掉的信号**（最重要）。找 `Parse failed` 和 `[parser] no signal`，逐条判断：
   哪些其实是**有效的开/平仓信号但解析器没认出来**？哪些确实只是闲聊/播报（例如喊单员的
   行情评论、盘前提醒、@everyone 通知），属于正确忽略？把前者单独列出来，附原始消息文本、
   时间、频道，并指出 `signal_parser.py` 里是哪条规则没覆盖。这是每天最该看的一件事。

   **`✏️  [edit]` 行必须单独看一遍。** 喊单员有"先发信号、几秒后编辑补喊价"的习惯
   （2026-08-05 实锤：23:51:00 发 "跟踪 $RKLB 每周 $80 看涨期权" 无价被正确拒单，
   23:51:15 编辑补上 "$1.35 填充 2%"，当时 `on_message_edit` 只写日志不解析，
   整单丢失）。现在这条路径会解析并发 TG（文案 `✏️ 消息编辑后成为信号（未自动下单）`），
   但**仍然不自动下单**——所以每条这样的告警都意味着一次需要人工决定的机会：
   核对当晚有没有出现、有没有被跟上。注意摘要里的原始消息是**收到时**的版本，
   编辑后的内容只在整晚日志的 `[edit]` 行里，两边对不上是正常的。

2. **实际成交质量**。每笔 OPEN：信号价 → 挂单限价 → `FILL_ADJUST` 后的真实成交价，
   算滑点。有没有挂出去没成交的？CLOSE 同理，看 `pct` 字段（止盈百分比）。

3. **持仓状态**。停机时还有哪些 OPEN？其中哪些是**过期的/隔夜不该留的**（注意
   `eod_force_close` 标记和期权到期日 —— option_code 里的 6 位是 YYMMDD）。
   有没有该强平但没平的？

4. **系统健康**。**先看启动横幅第一行的 `构建 = <sha> ... 工作区...`**
   —— 判断这一晚跑的到底是哪个构建。写进报告，并在结论里说清"某个修复
   有没有生效"时以它为准，不要靠推测。（2026-08-14 那晚跑的是修复提交之前的
   旧进程，两个修复一个都没生效；当时日志里没有这行，只能靠比对 commit 时间戳
   反推。工作区标成"有未提交改动"时，sha 并不能代表实际跑的代码。）

   然后统计断线次数（`on_disconnect`）、有没有触发 `Discord storm` /
   `Discord churn`；Telegram 发送失败几次；有没有 traceback / `ERROR` / `exception`。

   ⚠️ **`[notify] TG sent` 的缺席不等于没发 TG。** 那行日志只由 `notify()`
   包装函数打；错误路径上有一批**裸调 `send_telegram`** 的地方（成功时只记
   debug），日志里查不到。2026-08-14 的复盘据此得出"操作者手机上零告警"的
   **反向结论** —— 实际很可能收到了近千条。判断告警到没到，只能问人或查
   Telegram，日志不足以定论；写成"待确认"。
   掉线窗口和收到信号的时间点有没有重叠 —— 也就是说，有没有可能在盲区里漏了消息
   （注意 `_backfill_missed` 是否补上了）。

5. **今天要动的事**。最多 3 条，具体到文件和改法，按性价比排序。没有值得改的就直说
   "无"，不要凑数。

## 输出

**输出到哪里由调用方指定** —— 这份文件只管内容和格式。现在有两个调用方：
Claude 的定时任务（要求直接在对话里回答）、`ops/opus_review.sh`（要求写成
markdown 文件）。别自作主张换地方。

结构：

```
## TL;DR
（3-5 个 bullet，把最该知道的说完。有漏单的话第一条必须是它。）

## 1. 漏掉的信号
## 2. 成交质量
## 3. 持仓状态
## 4. 系统健康
## 5. 今天建议做的
```

写作要求：

- 用中文。
- 所有时间用本地时间（摘要里已经是了），需要对照美股时段时在括号里补 ET。
- 数字要具体（几条、几点几分、滑点多少），不要"多次"、"若干"、"表现良好"这种词。
- 拿不准的事标成"待确认"并说明怎么验证，不要猜一个说法当结论。
- 昨晚要是根本没有信号也没有异常，回答就写得很短 —— 短是对的，不要为了凑篇幅注水。
- **不要修改仓库里的任何代码**，这是复盘不是施工。
